# Database Architecture: ForeSeeMe

## Database Choice: Cloud Firestore

### Why Firestore?

1. **Real-time Sync**: Automatic client-server synchronization (ideal for adherence tracking)
2. **No Backend**: Serverless - no API development needed for MVP
3. **Firebase Ecosystem**: Integrates seamlessly with Firebase Auth
4. **Offline Support**: Future capability (already set up for later)
5. **Scalability**: Auto-sharding by document ID
6. **Security Rules**: Fine-grained access control at database level

## Firestore Structure

### Document Hierarchy

```
firestore-root (us-central1)
│
└── users/ [Collection]
    │
    └── {uid}/ [Document - Firebase Auth UID]
        │
        ├── profile/ [Subcollection - Health Profile]
        │   └── data/ [Single Document]
        │
        ├── medications/ [Subcollection - Medication Tracker]
        │   ├── {medId1}/ [Document]
        │   ├── {medId2}/ [Document]
        │   └── ...
        │
        └── adherence_logs/ [Subcollection - Adherence History]
            ├── {logId1}/ [Document]
            ├── {logId2}/ [Document]
            └── ...
```

## Collections & Schema

### 1. Users Collection

**Path:** `users/{uid}`

**Purpose:** Root user document (currently metadata only)

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| (empty) | - | - | Document exists for user isolation, no content |

**Reasoning:** Firestore requires document to create subcollections; also enables future user-level metadata.

---

### 2. Health Profile Subcollection

**Path:** `users/{uid}/profile/data`

**Purpose:** Store user's health information (location, conditions)

| Field | Type | Example | Notes |
|-------|------|---------|-------|
| `uid` | string | `"firebase-uid-123"` | Denormalized for easier querying |
| `city` | string | `"Lahore"` | User's location (air quality context) |
| `chronicConditions` | array<string> | `["Diabetes", "Hypertension"]` | Selected from constants |
| `lastUpdated` | timestamp | `2025-05-02T14:30:00Z` | Server-side timestamp, auto-managed |

**Document ID:** Always `"data"` (single profile per user)

**Example Document:**
```json
{
  "uid": "auth_uid_abc123",
  "city": "Lahore",
  "chronicConditions": ["Diabetes", "Asthma", "Hypertension"],
  "lastUpdated": Timestamp(seconds=1714744800, nanos=0)
}
```

**Firestore Path Structure:**
```
users/
  auth_uid_abc123/
    profile/
      data/  ← This single document stores all health profile data
```

---

### 3. Medications Subcollection

**Path:** `users/{uid}/medications/{medId}`

**Purpose:** Store medication prescriptions and reminder settings

| Field | Type | Example | Constraints |
|-------|------|---------|-----------|
| `uid` | string | `"auth_uid_abc123"` | Denormalized ownership |
| `name` | string | `"Metformin"` | Medication name |
| `dosage` | string | `"500mg"` | Human-readable dosage |
| `type` | string | `"pill"` | Enum: "pill" \| "syrup" |
| `frequency` | string | `"twiceDaily"` | Enum: "onceDaily" \| "twiceDaily" \| "thriceDaily" |
| `reminderTimes` | array<string> | `["08:00", "20:00"]` | 24-hour HH:mm format |
| `isActive` | boolean | `true` | Soft delete flag (never truly delete) |
| `createdAt` | timestamp | `2025-05-01T10:00:00Z` | Server-side, immutable |

**Document ID:** Auto-generated by Firestore (unique UUID)

**Example Document:**
```json
{
  "uid": "auth_uid_abc123",
  "name": "Metformin",
  "dosage": "500mg",
  "type": "pill",
  "frequency": "twiceDaily",
  "reminderTimes": ["08:00", "20:00"],
  "isActive": true,
  "createdAt": Timestamp(seconds=1714708800, nanos=0)
}
```

**Validation Rules:**
- `name` max 100 characters
- `dosage` max 50 characters
- `reminderTimes` length must match `frequency.expectedReminderCount`
- `reminderTimes` must be valid HH:mm format (00:00-23:59)

### 4. Adherence Logs Subcollection

**Path:** `users/{uid}/adherence_logs/{logId}`

**Purpose:** Track when user took medication and their status

| Field | Type | Example | Notes |
|-------|------|---------|-------|
| `medicationId` | string | `"med_uuid_456"` | Reference to medication document |
| `uid` | string | `"auth_uid_abc123"` | User ownership |
| `date` | string | `"2025-05-02"` | ISO 8601 date-only string |
| `status` | string | `"taken"` | Enum: "taken" \| "skipped" \| "pending" |
| `confirmedAt` | timestamp | `2025-05-02T08:15:00Z` | When user confirmed action (null if pending) |

**Document ID Format:** Deterministic (not auto-generated)
```
Format: {medicationId}_{date}_{time}
Example: med_uuid_456_2025-05-02_0800

Construction:
  medId: "med_uuid_456"
  date: "2025-05-02" (YYYY-MM-DD)
  time: "08:00" → "0800" (HH:mm → HHmm)
  logId = "med_uuid_456_2025-05-02_0800"
```

**Rationale for Deterministic IDs:**
- Enables upsert semantics (create or update)
- Prevents duplicate adherence records for same dose
- Query-friendly: query by exact dose
- Example query: `where('medicationId', '==', 'med_456').where('date', '==', '2025-05-02')`

**Example Document:**
```json
{
  "medicationId": "med_uuid_456",
  "uid": "auth_uid_abc123",
  "date": "2025-05-02",
  "status": "taken",
  "confirmedAt": Timestamp(seconds=1714731300, nanos=0)
}
```

**Status Transitions:**
- `pending` → `taken` (user marked as taken)
- `pending` → `skipped` (user marked as skipped)
- `taken` ← → `skipped` (can toggle for current/future dates only, past dates read-only)

## Data Types & Serialization

### Dart ↔ Firestore Mapping

| Dart Type | Firestore Type | Example |
|-----------|---|---------|
| `String` | String | `"Metformin"` |
| `int` | Number | `500` |
| `bool` | Boolean | `true` |
| `DateTime` | Timestamp | `Timestamp(...)` |
| `List<String>` | Array | `["08:00", "20:00"]` |
| `Enum` | String | `"twiceDaily"` |

### Timestamp Handling

**Server-side Timestamps (Recommended):**
```dart
// In model.toJson()
'lastUpdated': FieldValue.serverTimestamp()  // Auto-managed by Firestore
```

**Local Datetime:**
```dart
'createdAt': FieldValue.serverTimestamp()  // On first write only
```

**Date-only Strings (Special Case):**
```dart
// adherence_logs: store date as ISO string for efficient querying
'date': '2025-05-02'  // NOT a Timestamp - prevents timezone issues
```

### Enum Serialization

```dart
// Example: MedicationType
enum MedicationType { pill, syrup }

// toJson()
type.name  // Returns "pill" or "syrup"

// fromJson()
MedicationType.values.firstWhere((e) => e.name == json['type'])
```

## Firestore Security Rules

**File:** (Server-side, not in repo)

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Users can only read/write their own data
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth.uid == uid;
    }
  }
}
```

**Key Points:**
- User isolation by UID
- No public data exposure
- Automatic enforcement at database level
- Prevents cross-user data access

## Indexes & Query Optimization

### Default Indexes

Firestore automatically creates single-field indexes:

| Collection | Field | Type |
|-----------|-------|------|
| medications | `isActive` | Ascending |
| medications | `createdAt` | Descending |
| adherence_logs | `date` | Ascending |
| adherence_logs | `status` | Ascending |
| adherence_logs | `medicationId` | Ascending |

### Common Queries

**Get all active medications for user:**
```dart
db.collection('users').doc(uid)
  .collection('medications')
  .where('isActive', isEqualTo: true)
  .snapshots()
```
*No composite index needed (single field)*

**Get adherence logs for specific date:**
```dart
db.collection('users').doc(uid)
  .collection('adherence_logs')
  .where('date', isEqualTo: '2025-05-02')
  .snapshots()
```
*Single field query, no composite index needed*

**Get adherence logs for date range:**
```dart
db.collection('users').doc(uid)
  .collection('adherence_logs')
  .where('date', isGreaterThanOrEqualTo: '2025-05-01')
  .where('date', isLessThanOrEqualTo: '2025-05-31')
  .snapshots()
```
*Firestore automatically handles range queries on single field*

### Composite Indexes (None Currently Needed)

If future queries span multiple fields:
```dart
// Example (hypothetical): Get pending doses by medication
.where('medicationId', isEqualTo: 'med_456')
.where('status', isEqualTo: 'pending')
// Would require composite index if not on same date filter
```

Firestore will suggest index creation when needed.

## Database Constraints & Business Rules

### Medication Constraints
1. ✅ `reminderTimes.length == frequency.expectedReminderCount`
2. ✅ `reminderTimes` in ascending order
3. ✅ Each reminder time unique
4. ✅ `type` must be valid enum
5. ✅ `frequency` must be valid enum

**Enforcement:** Dart model validation (client-side), rules should be added server-side

### Adherence Log Constraints
1. ✅ `medicationId` must reference existing medication
2. ✅ `status` must be valid enum
3. ✅ `confirmedAt` only set when status != 'pending'
4. ✅ Log ID deterministic (prevents duplicates)
5. ✅ Cannot modify past date logs (check before write)

## Write Patterns

### Creating a Medication

```dart
final medication = MedicationModel(
  id: '',  // Will be set by Firestore auto-ID
  uid: userId,
  name: 'Metformin',
  dosage: '500mg',
  type: MedicationType.pill,
  frequency: MedicationFrequency.twiceDaily,
  reminderTimes: ['08:00', '20:00'],
  isActive: true,
  createdAt: DateTime.now(),
);

// Write to Firestore
final docRef = db.collection('users').doc(userId).collection('medications').doc();
await docRef.set(medication.toJson());
```

### Updating Adherence Status

```dart
final logId = AdherenceNotifier.generateLogId(medId, date, time);

final log = AdherenceLogModel(
  id: logId,
  medicationId: medId,
  uid: userId,
  date: date,
  status: AdherenceStatus.taken,
  confirmedAt: DateTime.now(),
);

// Upsert (create or overwrite)
await db.collection('users').doc(userId)
  .collection('adherence_logs')
  .doc(logId)
  .set(log.toJson());  // Deterministic ID enables upsert
```

### Deactivating a Medication

```dart
// Soft delete (never permanently delete)
await db.collection('users').doc(userId)
  .collection('medications')
  .doc(medId)
  .update({'isActive': false});
```

## Firestore Costs & Optimization

### Cost Breakdown (Approximate, May 2025)

- **Reads**: $0.06 per 100k reads
- **Writes**: $0.18 per 100k writes
- **Deletes**: $0.02 per 100k deletes
- **Storage**: $0.18 per GB/month

### Optimization Strategies

1. **Use streams selectively**
   - Only stream on active screens (DailyCheckInScreen)
   - Consider switching to periodic reads for inactive screens

2. **Batch operations**
   - Update multiple adherence logs in single batch when possible
   - Reduces write count

3. **Archive old adherence logs**
   - After 1 year, archive logs to separate collection
   - Keeps active collection lean

4. **Avoid full collection scans**
   - Always filter by date, medication, status when possible
   - Use indexes for common queries

## Backup & Recovery

### Firebase Backup (Automatic)
- Firestore provides automatic daily backups (7-day retention)
- Accessible via Firebase Console

### Manual Export (Recommended for production)
```bash
gcloud firestore export gs://foreseeme-83587-backups/backup_$(date +%Y%m%d)
```

### Recovery
- Restore from Firebase Console or `gcloud` CLI
- Point-in-time recovery not available (use backups)
